L’IA comprend votre bug, jamais vos secrets

FloutIA remplace uniquement les valeurs sensibles. Les noms de variables, les guillemets, les numéros de version et les URL publiques restent intacts pour que l’IA puisse diagnostiquer précisément.

Extrait collé (reste dans votre navigateur)

DATABASE_URL=postgres://admin:pwd99@db.internal:5432/prod
API_KEY="sk-proj-abc123def456ghi789"
PASSWORD=abc#def,ghi
Authorization: Basic dXNlcjpwYXNz
ERROR from 192.168.10.24 (C:\Users\marie\config.env)

DATABASE_URL=[CONNEXION_1]
API_KEY="[SECRET_1]"
PASSWORD=[SECRET_2]
Authorization: Basic [TOKEN_1]

Ce qui est neutralisé

  • Clés API et cloud : OpenAI (sk-), GitHub (ghp_, github_pat_), AWS (AKIA, ASIA), Slack, Google (AIza).
  • Authentification et chaînes : JWT, en-têtes Bearer et Basic, URI postgres, mongodb, mysql, mssql, redis, clés privées PEM et OpenSSH.
  • Variables .env : PASSWORD, SECRET, TOKEN, API_KEY, CREDENTIAL, y compris avec des caractères spéciaux dans les valeurs non quotées.
  • Réseau et système : IPv4 (hors numéros de version), IPv6, URL internes (.local, localhost, 192.168…), chemins /Users/, /home/, C:\Users\.

Questions fréquentes

Pourquoi ne pas simplement utiliser un chat temporaire ?

Même en mode temporaire, vos clés partent sur les serveurs d’un tiers. Avec FloutIA, les secrets restent dans votre navigateur et la réponse de l’IA est réinjectée localement en un clic.

Les URL de documentation et les mots-clés SQL sont-ils modifiés ?

Non. Les URL publiques sans identifiant et les mots comme POSTGRES restent en clair pour ne pas dégrader la réponse de l’IA.
